# 电氢氨园区协同优化调度：公开风电/光伏数据集核验报告

**检索日期：** 2026-08-14（GMT+8）  
**筛选要求：** 优先政府、国家实验室、大学、科研机构或国际能源组织；至少含风电或光伏时间序列；优先完整自然年（非闰年 8,760 小时）与 CSV/Excel；明确实际值、预测值、许可、引文与调度用途。

> **结论先行。** 若论文需要“实际出力 + 业务预测出力”来做日前/日内随机或滚动调度，首选德国联邦网络局 **SMARD**；若需要公开、可复现的概率预测场景，首选 NREL **ARPA-E PERFORM**，但其原始文件是 HDF5 而非 CSV。若需要可直接下载的全年小时级 CSV，优先采用 NREL **ReEDS 县级容量因子**（ZIP 内小时文件）、NREL **NSRDB/WIND Toolkit API 导出 CSV**，或 OPSD 的整包小时 CSV。EIA-930 则适合作为实际风光总量的历史验证基准。[1] [2] [3] [4]

## 三、CSV 获取与预处理建议

对于要求严格的论文复现，建议优先保留**原始下载文件**、下载时间、查询条件、时区和脚本版本。应把“资源数据”“模型化功率”“计量实际出力”“业务预测”分开描述：它们可都成为优化模型输入，但含义不同，不能互相替代。

| 任务 | 推荐来源 | 可直接获得 CSV？ | 处理要点 |
|---|---|---:|---|
| 日前/日内滚动调度，需风光预测误差 | SMARD | 是，下载中心导出 | 固定时区；将 15 分钟记录聚合至小时；对齐实际、日前、日内发布时间和预测提前期。 |
| 概率预测/随机规划 | PERFORM | 否，原始为 HDF5 | 根据 `time_index` 与站点元数据导出 CSV；以百分位构建场景，不要把模型化 actuals 表述为计量值。 |
| 美国园区年尺度容量配置 | ReEDS CF + NSRDB/WIND | ReEDS ZIP 内小时文件；NSRDB/WIND API CSV | 统一为容量因子；按 `P=CF×装机` 生成可用功率；在文中说明气象年。 |
| 系统级实际风光验证 | EIA-930 或 OPSD | EIA API 导出/整理；OPSD 直接 CSV | EIA 的 `value` 为 MWh/小时；OPSD 字段为 MW。先统一单位和时区，再做电解槽、储氢、合成氨调度。 |

> **关于本次附带的 CSV。** 附件 `EIA930_ERCO_Wind_Solar_2025_8760_UTC_missing_explicit.csv` 使用 EIA 官方 API 的 `ERCO`、`WND`、`SUN` 筛选生成。它含完整 2025 UTC 小时索引（8,760 行），其中 24 行在官方响应中缺失，已标记为 `missing_in_official_API_response` 并保持空值；没有任何插值、填零或虚构数据。该文件适合演示数据清洗与缺失处理流程，不宜在不处理缺失的情况下直接作为完整年的硬约束输入。

## 四、建议的论文表述与方法边界

若研究主题是“电—氢—氨园区协同优化调度”，建议以 **SMARD 或 PERFORM** 构建“预测—实际偏差”情景，以 **NSRDB/WIND/ReEDS** 构建“园区所在地资源—装机规模”情景，并把氢储罐、合成氨负荷、弃风弃光、购电和备用约束置于同一小时级能量平衡中。EIA-930 和 OPSD 更适合作为外部有效性检验或灵敏度分析，而不是项目级可再生能源的唯一输入。

使用全部来源前，应在方法章节明确：时间戳是 UTC 还是当地时区、夏令时如何处理、功率（MW）与小时电量（MWh）如何换算、缺失值策略是什么，以及“actual”究竟代表计量数据还是模型化基准。对于非闰年请验证 8,760 行；闰年有 8,784 小时，不能直接按 8,760 截断而不加说明。
